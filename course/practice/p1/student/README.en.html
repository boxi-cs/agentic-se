    P1: Build a minimal coding agent

    Objectives

    Explain and implement an observation-action loop (LO1): ask for an action, dispatch read, write or bash, return the observation, and stop. Predict model performance before measuring it, then use a failed check to improve your implementation.

    You implement only Agent.run in agent_skeleton.py, within 300 nonblank, noncomment lines including any helpers you add to that file. The course supplies the model adapter, workspace tools, context compaction, task inputs and trace writer in lab_runtime.py. Tests do not count toward the implementation limit. You do not rebuild the launcher or its security checks.

    Prerequisites

    Complete Week 0 setup for the shared safety admission, launcher and approved hosted or replay access.

    Keep the profile, version and digest returned by the Week 0 resolver, and the approved hosted or replay route. Run the commands below from the course checkout or unpacked student package root. Create a separate lab01-work directory in your editor and copy only agent_skeleton.py, lab_runtime.py, exercise.py and the five tasks/*.json files into it, retaining the tasks/ subdirectory. Keep results outside that input directory. Do not copy the whole private course checkout.

    Tasks

    Week 1: Predict, generate, verify

    Complete the four required tasks in the calibration exercise. For each task, save your own time/pass prediction before generation; run the hosted or replay route once through its supplied launcher controller; inspect the candidate as text; and verify it with the public cases. Preserve wrong answers and technical failures. A later revision is a new attempt, not a replacement first attempt.

    The required IDs are lab01-cal-001, lab01-cal-002, lab01-cal-003 and lab01-cal-005: signed sum, stable ordering, inclusive clamping, and whitespace with word order. The other sixteen catalog tasks are optional practice. Keep calibration.csv, the four task JSON records and corresponding candidates together. The linked instructions provide the exact start, finish, validation and report commands. At the first workshop checkpoint, show one prediction and its observed result. Ask for help if setup or waiting prevents you from making progress; a low pass rate is evidence to explain, not a reason to invent successes or repeat until every first attempt appears correct.

    Save this set for Week 1 formative feedback. Reference the same commit/evidence ID in Week 2 and your P1 portfolio sample; keep the original attempts when revising.

    Week 2: Implement and observe the loop

    The supplied interface is Agent(model, tools, max_steps, context_limit) and Agent.run(task) -> Trajectory. Start with one user message containing the task. For each permitted turn:

    1. Pass compact(history, context_limit) to model.chat. It retains the task, bounds long observations and drops old action/result groups when necessary.
    2. Append the returned assistant message, including its tool_calls.
    3. With no tool calls, return Trajectory(history, "final") immediately. Empty answer text still counts as final when there are no calls.
    4. Otherwise, dispatch each named tool with its arguments. Append a tool message containing role: "tool", the matching tool_call_id, and string content.
    5. If the turn budget is exhausted, return Trajectory(history, "step_limit").

    Keep the full history for the returned trajectory; compact the copy sent to the model. Handle an unknown tool or refused operation with a short safe observation, without exposing paths or environment values. Do not keep calling after final.

    For example, returning immediately after a write call creates the file but misses verification. Inspect completion.json: it should show the subsequent bash observation and then the final answer. Fix the stopping branch and run again into a new result directory. That revision is your first formative feedback checkpoint.

    The bash tool deliberately accepts only python -B workspace-file.py with plain arguments. It runs that file through bash inside the launcher. It is not a general shell. Use the supplied verify.py commands from the task responses; imports and nested subprocesses remain subject to the same container limits.

    Verify all five tasks

    The public tasks are course-authored deterministic replays. They isolate loop bugs from model variability; they are labelled fake/fake-v1 and are not real model measurements. Actual hosted-route calibration belongs to the Week 1 activity.

    Task Work product Verification in the task
    create greeting.txt Exact text and final newline
    repair numbers.py Failing signed-sum examples now pass
    refactor prices.py Extracted helper preserves results
    cli hello.py CLI output matches its argument
    answer answer.txt Read two source files and check the answer

    Replace VERSION and DIGEST with your resolver output. Run once per task, changing both --task create and the output name to repair, refactor, cli and answer. Every output directory must be new; for a revision use a name such as lab01-create-revised.

    sh scripts/course-sandbox --profile approved-hosted --version VERSION --digest DIGEST \
  --workspace lab01-work --output lab01-create \
  -- python -B exercise.py --task create

    The unmodified starter raises NotImplementedError; it has no working loop yet. With your loop implemented, inspect the launcher exit code, exported product and completion.json. For each verification command, check for exit_code: 0 and stdout: "verified\n" in its tool observation. Check that the last assistant turn has no calls and stop_reason is final. An exported file alone is not proof of success. The fixed responses and public checks are visible so you can diagnose failures; copying their answers does not implement a general loop.

    trajectory.jsonl is the minimal per-call trace for this replay. Inspect consecutive run.sequence values starting at zero and one run ID. Each record contains the input messages and returned assistant step; only that last step carries this call's usage and latency. not_collected fields are lengths/digests, not missing text to fill in. Use completion.json locally to understand these synthetic turns, and submit only the requested minimal trace plus your short explanation.

    Also test an early final response and a sequence that reaches max_steps; explain why each stops. Use an oversized observation to check context compaction. If stuck, first check tool-result IDs, then the final branch, then the context copy. Ask for feedback before adding more tools or a more elaborate agent architecture.

    Deliverables

    Keep one P1 work record and use the same evidence through feedback and P1:

    • Week 1 checkpoint: the four-task CSV, matching JSON records and candidates, with a brief explanation of one prediction and observed result.
    • Week 2 checkpoint: agent_skeleton.py, your tests, five minimal JSONL traces, and the required recorded-session dissection table and answers from the Week 2 activity labelled by task, work products and verification results. Explain one loop failure, its fix and the repeat check; reference the Week 1 evidence ID.
    • P1 portfolio sample: select this existing evidence, explain how the loop and tool boundary affect a result, and show one revision after feedback. Write your explanation independently; no separate comprehensive report is required.

    P1 is individual. Include your own verification, even if you discussed an error with classmates. Keep one AI-use note across this practice unit and refer to its ID when reusing the evidence. Write your prediction and brief reflection yourself, without AI. Remove credentials and unrelated personal data before pushing; do not submit environment files or a full conversation export. If a required trace cannot be safely exported, record the technical failure and existing contemporaneous evidence in your same explanation, then use the course's announced supplement process.

    Grading

    P1 is a practice unit with feedback and revision. P1 contributes 4 points to the 10-point individual practice portfolio by reusing selected P1 evidence; P1 has no separate course mark. Your independent explanation and response to feedback matter. Completing optional tasks does not increase the maximum.

    The diagnostic rubric remains 100 points: task contracts 60, trajectory and limit checks 20, required calibration evidence 10, and human-reviewed readability 10. Each of the four required, internally consistent calibration records contributes 2.5 diagnostic points. Optional records cannot substitute for a required task or add points. Calibration measures consistent evidence, not how often the model was right; neither model correctness nor self-reported time calculates your P1 mark.

    Use the five public checks and diagnostic feedback to revise. public_only means practice feedback; pending_human means the readability item still awaits review. Those 10 human points are within the diagnostic maximum of 100. Your instructor assesses P1 from the announced portfolio criteria and your selected work, checks, independent explanation and revision. Preserve technical-failure evidence for review; missing feedback is not a final zero.

    AI use rules

    Yellow: approved hosted API route and course sandbox only, as linked in Prerequisites. Predictions and reflection are red: no AI. You may choose not to use AI for the loop implementation; the required model-calibration activity still needs its approved execution or an instructor-approved equivalent.

    Use a truthful note in your existing explanation, for example:

    P1, evidence L1-01. I used [actual model/tool] for [purpose]. I personally verified [checks and result IDs] and changed [one decision]. My reflection is my own. Week 2 refers to this same note.

    If no AI helped your loop, say that explicitly and distinguish it from Week 1's model measurements. Correct mistakes in the same record rather than fabricating an earlier session.

    Estimated time

    Plan 11 hours total, including both workshops and the required session dissection: about 3 hours for calibration, 3 for the loop and five tasks, 2.5 for the recorded-session dissection, and 2.5 for verification, feedback, revision and your brief explanation. These are planning values, rounded up from the activity estimates, not measured student times or cutoffs. Waiting and help count. Seek support at the workshop checkpoints or when the plan no longer fits; reaching the time box does not automatically cost marks.
