    CP1 practice paper

    This paper practises CP1, the week 6 checkpoint. It has the real paper's format, length, question types and marks. The session and the code were written by the course for this practice paper; they come from no real project and appear on no real paper. How to sit and mark it is on the practice papers page. The marking points and worked answers are on a separate page: open it only when you have finished.

    Conditions. Work alone for 30 minutes with no device, model, agent or reference material; the paper prints everything you need. Keep answers short, and cite turns and line numbers so that a marker can find what you mean.

    Marks. Ten points of one mark each. The real paper records raw marks × 0.75, so 7.5 at most.

    Suggested pace. The first half ends after Q2. If you sit the paper in two halves, stop there at minute 15 and take Q3 and Q4 in one more 15-minute sitting.

    Minutes What to do
    0–4 Read Part 1 and answer Q1
    4–9 Read Part 2: the rules, the listing, the callers, the tests and the report
    9–15 Q2 (end of the first half)
    15–21 Q3
    21–27 Q4
    27–30 Check your answers

    Part 1: an agent session

    A coding agent was given this task in the repository of a food bank's donation desk:

    Rename the function donor_label to receipt_name everywhere in the project, and keep the tests passing.

    System prompt (extract). "You are a coding agent working in one repository. Use the tools to search and change files. After a rename, search the whole project for the old name before you finish. Reply without a tool call when the task is complete."

    Tools.

    Tool What it does and returns
    find(pattern) Searches every file in the project for the pattern. Returns each matching line as file:line: text, or no matches, or error: <reason> when the search did not run.
    replace(path, old, new) Replaces every old with new in one file. Returns replaced and the number of replacements.
    run_tests(name) Runs one test file. Returns the counts, for example 6 passed, 0 failed.

    Controller. The controller executes every tool call and returns its result to the agent. A reply without a tool call ends the session with stop reason final; the tenth tool call ends it with stop reason tool_limit.

    Turn Agent's call or reply What the agent got back
    1 find("def donor_label") receipts.py:8: def donor_label(donor):
    2 replace("receipts.py", "donor_label", "receipt_name") replaced 3
    3 run_tests("test_receipts") 6 passed, 0 failed
    4 find("donor_label(") error: unclosed "(" in pattern
    5 Reply, no tool call: "Done. donor_label is now receipt_name. No file in the project uses the old name any more, and all 6 receipt tests pass." Session ends, stop reason final

    Q1 (2 marks)

    (a) Which turn's claim goes beyond what the results show? Name the part with no evidence behind it and say, by turn number, what evidence is missing. (1)

    (b) Why did the session stop at turn 5, and why could the system prompt's instruction to search the whole project before finishing not stop that claim? (1)

    Part 2: a code listing

    The same food bank weighs every donated item. Its rules:

    • Every entry is a whole number of 1 or more, one space and a unit, g or kg: for example 750 g or 3 kg. 1 kg is 1000 g.
    • to_grams returns the weight of one entry in grams.
    • An item of 5000 g or more needs two people to lift. A receipt shows the item's weight in grams, for example 2000 g.
    01 KG = 1000  # grams in one kilogram
02 HEAVY = 5000  # grams: an item this heavy or heavier needs two people
03
04 def split_weight(entry):
05     """Split an entry such as "750 g" into (750, "g")."""
06     amount, unit = entry.split()
07     return int(amount), unit
08
09 def to_grams(entry):
10     """The weight of one donated item, in grams."""
11     amount, unit = split_weight(entry)
12     grams = amount
13     if unit == "kg":
14         grams = amount * KG
15     return amount
16
17 def total_grams(entries):
18     """The weight of all the items together, in grams."""
19     total = 0
20     for entry in entries:
21         total += to_grams(entry)
22     return total
23
24 def two_person_items(entries):
25     """The items that need two people to lift."""
26     return [entry for entry in entries if to_grams(entry) >= HEAVY]
27
28 def receipt_line(entry):
29     """The weight printed on the donor's receipt."""
30     grams = to_grams(entry)
31     if entry.endswith("kg"):
32         grams = grams * KG  # added in April: receipts showed kg items too light
33     return f"{grams} g"

    entry.split() cuts the text at the space, so "3 kg".split() is ["3", "kg"], and int("3") is the number 3. entry.endswith("kg") is true when the text ends in kg. f"{grams} g" is the value of grams followed by a space and g, for example "2000 g" when grams is 2000.

    Callers of to_grams.

    Caller Lines Uses the result for
    total_grams 17–22 the weight of all the items together
    two_person_items 24–26 which items need two people to lift
    receipt_line 28–33 the weight printed on a receipt

    These tests exist, and every one of them passes on the listing.

    assert to_grams("750 g") == 750
assert total_grams(["200 g", "450 g"]) == 650
assert two_person_items(["6000 g", "900 g"]) == ["6000 g"]
assert receipt_line("2 kg") == "2000 g"

    What was reported. A donor brought a 3 kg bag of rice and a 500 g bag of lentils. total_grams(["3 kg", "500 g"]) returned 503. By the rules the total is 3500.

    Q2 (3 marks)

    (a) Name the function and the line where the fault is, and say briefly what is wrong there. (1)

    (b) Follow the reported call from total_grams down to that line, writing the values that matter at each step, until you reach 503. (1)

    (c) For which entries does that line give a wrong weight, for which a right one, and why? (1)

    End of the first half.

    Q3 (3 marks)

    A regression test for this fault is one assert on a function from the listing.

    (a) Write the assertion. Its input must be one that the printed listing gets wrong. (1)

    (b) Name the printed rule that your expected value comes from. (1)

    (c) Give the value the printed listing returns for your input, and the value it will return once your Q4 repair is made. (1)

    Q4 (2 marks)

    (a) Give the smallest repair: the line or lines to change, and their new text. (1)

    (b) Take each caller in the table in turn. After your repair, is its result right, and do its own lines need to change? Where they do, name the lines and give an input that shows why. (1)

    Stop when the time is up. Then mark your paper with the marking points and worked answers.
