Background agent pipeline for the practice repository (course-written example)

This describes a pipeline; it is not the configuration of any product.

Trigger:    a maintainer adds the label agent-ready to an issue
Workspace:  a fresh copy of the repository at the default branch; no network
Reads:      the issue text and the repository files
Hands back: a branch, a pull request with a description, and a run report

What the agent's token may do:
G1  Create and push branches whose names start with agent/
G2  Open a pull request from an agent/ branch into the default branch
G3  Change any file in the repository, the tests included
G4  Merge its own pull request when the required check passes

Required check: python -B test_durations.py -v, run on the pull request's branch
Merging:        G4 merges without waiting for a person
