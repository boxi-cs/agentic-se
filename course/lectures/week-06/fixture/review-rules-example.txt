Review rules for the document-edit guard (course-written example)

Each rule says where it came from and how a reviewer checks it. A comment that
cites a rule points at a diff line and gives an input or file that shows the problem.

R1  Every role path keeps the active check.
    Source: contract "Inactive accounts cannot edit"; past defect, an inactive owner was allowed.
    Check: for owner, staff and both roles, an inactive input is denied by a check that ran and passed.

R2  The implementation and the checks that judge it do not change in the same PR.
    Source: a past change in which a test was edited to allow inactive owners.
    Check: the diff touches access.py or check_access.py, not both.

R3  Inputs stay Python booleans; the change adds no parsing and no new input type.
    Source: contract "Inputs are booleans"; issue out of scope "Parsing strings".
    Check: the diff adds no str handling, conversion or default argument.

R4  The PR answers the four explanation questions with an actual launcher result.
    Source: the course explanation gate.
    Check: "What did you personally verify?" names the run and its exit code.
