# AGENTS.md for ci-dashboard

ci-dashboard is a Flask dashboard over synthetic CI records. Read this file before you
change anything. It lists the only commands to run and the rules a change must keep.

## Run and test

Run each `launch.py` command from the package root. Each one goes through the project
launcher, which runs the app in a disposable copy with no network. Never run `manage.py`
or `make` directly.

- Create the database: `python3 -I launch.py init-db`
- Run the local job: `python3 -I launch.py run-job`
- Smoke test: `python3 -I launch.py smoke`. Expect exit 0 and
  `PASS: login, list, detail, and local job smoke`.
- Unit tests: none yet. `launch.py` has no test action; add the command here when it does.

## Before every commit

Run the course pre-commit hook on every changed file. It stops a change to a file listed
under Boundaries and an unused import in a Python file. From the course root, create a
new workspace such as `week05-hook`, copy `lectures/week-05/example/pre_commit.py` into
it, and copy each changed Python file into it at its repository path. Then run this
from the course root, with `VERSION` and `DIGEST` from the course resolver and every
path that `git diff --name-only` prints listed in `paths`:

```sh
sh scripts/course-sandbox --profile offline --version VERSION --digest DIGEST --workspace week05-hook -- python -B pre_commit.py '{"event":"before_commit","paths":["domains/labels.py"]}'
```

Exit 2 means fix the findings and run the hook again. Commit only after exit 0, and keep
that launcher result with the commit.

## Invariants

A change that breaks a rule's check is not done.

- **I1. The main user path works.** Sign in, list records, open one, run the local job.
  Check: `python3 -I launch.py smoke` exits 0.
- **I2. Synthetic data is reproducible.** One seed and count give one sample.
  Check: run `python3 -I launch.py sample --seed 7 --count 12` twice; the outputs match.
- **I3. The app stays local.** Start-up refuses a `config.toml` whose `host` is not
  `127.0.0.1` or whose `job_target` is not `local`.
  Check: set `host = "0.0.0.0"`, run `python3 -I launch.py init-db` and expect exit 2;
  restore the file and expect `PASS: database initialized`.

## Boundaries

- All data is synthetic. The `demo` account's teaching password is public; never use a
  real password or real build logs.
- Do not change `launch.py`, `Dockerfile`, `pyproject.toml` or `uv.lock` in a feature
  change. A dependency change is its own reviewed change. The pre-commit hook stops a
  commit that changes one of these files.
- Do not install packages. Run only the commands this file lists; ask before any other.

## Report

End every change with three lists: each file you changed; each command you ran, with
its exit code; and anything you did not check. Say "not checked" rather than guessing.
