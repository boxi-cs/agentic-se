    Week 1 self-check answer guidance

    Try each prompt first. Then compare the evidence and limits below with your own record.

    Q1a–Q1d: Four events

    Q1a. Learning next-token prediction from code is pretraining. Q1b. Learning from instruction-response demonstrations is supervised fine-tuning. Q1c. Adjusting sampled answers using rewards is reinforcement learning. Q1d. Reading a test result into the current context is inference or tool execution.

    Q1e–Q1f: Parameters and rewards

    Q1e. The first three events change learned parameters; the fourth supplies information to the current run. Q1f. A test-based reward checks only the cases encoded by its tests, so it can give the same signal to candidates that differ on an untested requirement.

    Q2a–Q2d: Available context

    Q2a. The repository's whitespace rule is missing. Q2b. Perform an allowed read of the contract and record its revision. Q2c. No. The read supplies context; a requirement-based check is still needed. Q2d. No. A read does not retrain model parameters.

    Q3a–Q3e: Normalization

    Q3a. "OK" distinguishes the candidates. Q3b. The contract requires passed. Q3c. The trim-only candidate returns unknown. Q3d. Normalize with raw.strip().lower() before lookup. Q3e. Keep a mixed-case case such as "OK" alongside the padded lowercase case and an unknown case.

    Q4a–Q4d: Execution evidence

    Q4a. The proposal was to run a test. Q4b. The controller denied it. Q4c. A completed test observation on the current candidate is missing. Q4d. Inspect the denial, then use an allowed route; never bypass the safety boundary or accept the final sentence as evidence.

    Q5a–Q5f: First attempts

    Q5a. Three of four tasks were completed. Q5b. The original record has two successes, one failure and one unknown. Q5c. A later repair is a separate attempt and does not erase the first-attempt result. Q5d. The mean signed time error is +2 minutes. Q5e. One of two binary pass predictions is wrong, so the error is 0.5. Q5f. Retain the exact task, candidate, command result, revision and timing or waiting record; those observations separate model behavior from execution failure or waiting.

    Q6a–Q6d: Missing domain meaning

    Q6a. The existing contract returns unknown. Q6b. Ask whether completed includes unsuccessful runs and where that outcome is represented. Q6c. Protect and rerun the existing recognized, padded and unknown-status cases. Q6d. Trimming changes representation, not the product meaning of a new status.

    Q7a–Q7d: Caller behavior

    Q7a. The rows retain IDs 17, 18 and 19 in order, with labels failed, passed, unknown, and failed: 1. Q7b. Assert the complete ordered rows as well as the count. Q7c. Helper tests cover label mapping, not whether the caller drops rows. Q7d. Delegate a bounded caller inspection and patch; inspect the diff and completed full-output regression before accepting it.

    Spaced retrieval

    Retrieval 1. Reading, planning and writing a prediction may continue; generated code and model execution must wait for a passing launcher safety check. Retrieval 2. Record the actual verification command result for the current revision, including the tested artifact and stop status.

    Decision with sufficient evidence

    The checked labels, count and ordered IDs support a bounded decision for the recorded revision and cases. The evidence does not establish behavior for every string or caller.
