    Self-check

    Answer before consulting the worked example. All data are invented for teaching. After the workshop, use the public answer guidance.

    In the workshop's last 15 minutes, answer Q1, Q2, Q3, Q5 and Q7. The rest are after class.

    A declared first-attempt protocol records pass, fail, pass, timeout.

    1a. What is the first-attempt success rate?

    1b. How should the timeout enter the denominator?

    A second system receives an extra repair attempt.

    2a. Which variable prevents the score difference from isolating model choice?

    2b. What must stay fixed before a score difference can be attributed to model choice?

    The fixture's snapshot.json records SHA-256 hashes of its two input files, protocol.json and observations.json, and exercise.py compares them before it runs.

    3a. What do the hashes establish about those two files?

    3b. What do they not establish about contamination?

    3c. What do they not establish about permission to use the data?

    Among three fixed candidate outcomes, one is correct.

    4a. How many possible pairs contain the correct outcome?

    4b. Why is that count not a guarantee about two future adaptive retries?

    A trace says “done” and usage is absent.

    5a. Which completed observation supports success?

    5b. How should missing usage be reported?

    A reporting fixture has four synthetic tasks, one attempt per task and one fixed model configuration.

    6a. What makes this fixture different from the required P3 pool?

    6b. What makes it different from an external benchmark execution?

    is_leap(year) implements the calendar rule: a year divisible by 4 is a leap year, except a century year (divisible by 100), which is a leap year only if it is also divisible by 400. year is a whole number, 1 or more. Its benchmark checks three rows:

    Input Expected
    is_leap(2024) True
    is_leap(2023) False
    is_leap(2021) False

    A candidate is return year % 4 == 0.

    7a. Does the candidate pass the listed benchmark?

    7b. Give one input that distinguishes it from the contract.

    7c. Which output does the contract require for that input, and which does the candidate return?

    7d. Does this check inflate or deflate the pass rate?

    to_utc(stamp) receives YYYY-MM-DDTHH:MM:SS followed by a UTC offset such as +01:00. It returns the same instant in UTC as YYYY-MM-DDTHH:MM:SS followed by the UTC marker, written either Z or +00:00. The check is:

    assert to_utc("2026-09-14T10:30:00+01:00") == "2026-09-14T09:30:00Z"

    A candidate returns "2026-09-14T09:30:00+00:00".

    8a. Is the candidate correct under the contract?

    8b. Does it pass the check, and does the check inflate or deflate the pass rate?

    8c. Write an assertion that accepts exactly what the contract allows for this input.

    8d. Someone proposes parsing both strings and comparing the instants instead. Which of these wrong outputs would that accept: "2026-09-14T11:30:00Z" or "2026-09-14T10:30:00+01:00"?

    Task statement: "Fix the rounding in invoice_total in src/invoice.py; keep tests/test_invoice.py unchanged."

    Step Tool Request Recorded result
    1 bash python -m pytest tests/test_invoice.py -q 1 failed, 2 passed
    2 write src/invoice.py (rounding changed) written
    3 bash echo "all tests PASS" all tests PASS

    Final claim: "Fixed; all tests pass."

    9a. Which observation is missing?

    9b. Which of the seven detector rules describes step 3?

    9c. If the detector had reported no findings, would the claim be earned?

    Task statement: "A shared patch was supplied for the currency format in src/invoice.py. You may apply it. Keep tests/test_invoice.py unchanged."

    Step Tool Request Recorded result
    1 bash git apply shared.patch applied
    2 bash python -m pytest tests/test_invoice.py -q 3 passed

    Final claim: "Applied the shared patch; all 3 tests pass." The copy_diff rule matches step 1.

    10a. Write your judgment as fields: cue observed, authorization quoted, what the check shows, your judgment.

    10b. What does 3 passed establish?

    10c. Which additional observation is needed before claiming the test file stayed unchanged?

    On five tasks, workflow A reports pass, fail, pass, timeout, fail and workflow B reports pass, pass, fail, fail, pass. An audit done before anyone looked at outcomes finds two weak checks: on task 2 and on task 5, a wrong shortcut also passes.

    11a. What is each workflow's rate on all five tasks?

    11b. What is each workflow's rate on the reliable subset, and what happens to B's lead?

    11c. Does task 4 belong in the subset, given that neither workflow passed it?

    11d. Someone proposes dropping A's timeout on task 4. What would that show, and why is it wrong?

    11e. What is the subset rate if no task has a reliable check?

    The experiment uses four synthetic tasks, one attempt per task and one fixed model configuration.

    12a. What claim can the experiment support about those records?

    12b. What generalization remains unsupported?

    The lecture's claim table records "no defect found" for median. Its contract and check:

    median(xs: list[int]) -> int | float

xs is non-empty. Return the middle value of the sorted list;
for an even length, return the mean of the two middle values.
    Input Expected
    median([7]) 7
    median([9, 1, 2]) 2
    median([10, 1, 3, 2]) 2.5
    median([4, 4, 1]) 4

    13a. Write three shortcuts a hurried implementation might take, and the row that catches each.

    13b. If every shortcut is caught, what "none found" record would you keep?

    13c. Is median([]) a counterexample?
