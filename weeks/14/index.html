Agentic Software Engineering · Week 14

Has it ever failed?

Demonstrate and defend the result

9:35 · subtitles: English, 中文 · download

The idea

Claim only the scope you checked, and count a check as evidence that it would stop a bad change only once you have seen it fail. In the practice packet the code predicts that a guest is denied, but the evidence matrix never observed a guest, so acceptance extends only to the checked cases; a peer's changed input either reuses an observation or names the next check. The same rule decides the software-factory claim stage by stage. The Evaluate stage's regression gate has been seen to fail on an agent's "robust" evaluator change and to pass on the current evaluator, so it is a candidate for unattended merging, not yet unattended: its cases sit where the agent could write, the candidate runs inside the checker, and the stop rule has never been exercised. Its nine cases also pass a trim-only escape until that escape becomes a tenth case. The model audit has never been seen to fail and pass on known inputs, so it runs unattended only as a source of hypotheses.
