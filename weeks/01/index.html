A plausible patch and a failing build

The idea

A plausible patch that passes its two existing tests can still break the contract. A test derived from the contract (not from the patch) can expose the omitted rule. The same habit runs through the rest of the week: a generated program is not an executed one, context is not retraining, each event in an agent's trace establishes only its own thing, and a repaired helper can still leave its caller wrong.
