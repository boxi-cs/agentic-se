Agentic Software Engineering · Approach

How this course works

Agents generate. You verify, decide and explain.

A coding agent can produce a plausible change in seconds. This course is about what comes after that: deciding whether the change is right, whether it is safe to run and whether you can explain it to someone who was not there.

Generate, then verify

Every example in the course shows both steps. The agent proposes; you check. A passing test you can rerun is evidence. An agent that says "done" has made a claim, and a claim is where your work starts.

Start from a decision you can get wrong

A class opens with a question that has a wrong answer. You save your own prediction before any discussion. Then you inspect a candidate or a trace, run a check that tells the possible answers apart, revise after feedback and try the same idea on a changed input. Saving the prediction first shows you what you actually expected, not what you remember expecting.

Decide instead of regenerating

When a candidate passes, choose what to do next: accept it, narrow the task, recheck something specific or stop. Asking for another generation helps only when it answers a question you can name.

One repository, followed for fourteen weeks

The teacher follows one continuing case: a CI dashboard that tells a developer which build failed and what to inspect next. From week 3 you work in your own copy of ci-dashboard and carry one path through every stage. You also build a complete feature in a real open-source project, through two or three approved contributions.

WeeksQuestionWhat you carry forward
1-3What happened, and where should a bounded agent act?A counterexample, a controller trace and a request-path map
4-8What does the user need, and does the change keep required behavior?An executable specification, a reviewed PR, tests and security regressions
9-11Can the experiment, the evaluator and the running service be trusted?A frozen protocol, evaluator checks and recovery evidence
12-14What survives another person's review and actual use?A verified audit response, a tested iteration and a result you explain yourself

Each stage reuses the work from the one before. You keep one artifact, its verification and a short explanation in your own words, and attach your AI-use note once.

You can explain it without the agent

Agents are welcome in open work. Your understanding is assessed without them: two short checkpoints and an oral defense, 40 of the 100 points, are done without AI. In the defense you meet a changed input and decide what to do. If you verified your own work during the term, you have already practiced this.

Mechanisms before tools

Tools change quickly. The course teaches what stays useful across them: what context a model saw, which tool calls it could make, when it stopped and what evidence supports the result. You build a small agent yourself in week 2 so that later tools are less mysterious. Optional features and extra tool integrations are never required for full marks.

Safety is part of the method

Code and commands that a model writes or suggests run inside the course launcher, not directly on your machine. Week 0 setup explains it once.
